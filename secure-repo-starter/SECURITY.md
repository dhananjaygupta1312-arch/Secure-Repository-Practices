# Security Policy

## Supported versions

| Version | Supported |
|---|---|
| latest release | Yes |
| previous minor | Security fixes only |
| older | No |

## Reporting a vulnerability

**Please do not open a public issue for security problems.**

Report privately using either:

- GitHub: **Security** tab → **Report a vulnerability** (private vulnerability reporting)
- Email: dhananjaygupta1312@gmail.com

Include: affected version/commit, a description and impact, reproduction steps or proof of concept, and any suggested fix. Please do not include real user data or live credentials in your report.

## What to expect

- Acknowledgement within **3 business days**
- Initial assessment within **7 days**
- Fix or mitigation plan communicated as it develops; target **90 days** to coordinated disclosure
- Credit in the advisory if you'd like it

## Scope

In scope: this repository's code, build and release pipeline, and published packages.
Out of scope: social engineering, physical attacks, denial-of-service via volumetric traffic, third-party services we don't control.

## Safe harbor

We will not pursue legal action against researchers who act in good faith, avoid privacy violations and service disruption, only test against their own accounts or data, and give us reasonable time to fix before disclosure.

## If you find a leaked credential

Report it privately as above. Do not test or use the credential.
